# Design

## Context

Код пишется с нуля в корне `with-spec/`; готовых модулей нет. Мотивация — в `proposal.md`, требования — в `specs/tracker/spec.md`. Состав файлов задан постановкой: `index.html`, `styles.css`, `app.mjs`, `domain.mjs`, `tests/acceptance.test.mjs`. Ограничения: без CDN, библиотек и ключей; тесты — на `node:test`; страница должна работать через простой статический сервер, а при `file://` — насколько позволяет браузер.

## Goals / Non-Goals

**Goals:**
- Чистая бизнес-логика без DOM в `domain.mjs`, которую можно тестировать из Node.
- Тонкий UI-слой `app.mjs`, который только связывает DOM с функциями домена.
- Явное разделение: автотесты покрывают расчёты и валидацию, интерфейс проверяется вручную (T1–T5).

**Non-Goals:**
- Фреймворки, сборка, TypeScript, редактирование задач, сортировка, обязательная кнопка сброса.
- Гарантии localStorage при `file://` (зависит от браузера).

## Decisions

1. **Разделение domain / app.** `domain.mjs` экспортирует чистые функции: `createInitialTasks()`, `parseHours(raw)`, `validateTask({title, hours})` → `{ok, errors:{title?, hours?}, value?}`, `computeSummary(tasks)` → `{totalHours, doneHours, progress}`, `filterTasks(tasks, filter)`, `addTask`, `removeTask`, `toggleTask` (без мутации, возвращают новый массив). *Альтернатива:* логика прямо в обработчиках DOM — отвергнута: её нельзя автотестировать без браузера.

2. **Валидация часов через строку.** Вход — строка из поля. Пустая или пробельная строка → ошибка (не 0). Запятая заменяется на точку; формат проверяется регулярным выражением `^\d+(\.\d+)?$` (отсеивает минус и «abc»), затем диапазон 0.5–24 и кратность 0.5 (`n*2` — целое). Поле — `type="text"` с `inputmode="decimal"`, а не `type="number"`: так проверка и тексты ошибок едины во всех браузерах, а запятая работает. *Альтернатива:* `type="number" step="0.5"` — отвергнута из-за нативных подсказок и разного поведения с запятой.

3. **Прогресс.** `total === 0 ? 0 : Math.round(100 * done / total)`. Для значений, кратных 0,5, суммы в float точны, накопленной ошибки нет.

4. **Фильтр — только представление.** Состояние `filter` хранится отдельно от `tasks`; `computeSummary` всегда получает полный массив, `filterTasks` — только для рендера списка.

5. **Рендер.** Один `render()` перерисовывает сводку, список и ошибки из состояния `{tasks, filter, errors}`. Строки создаются через `createElement`/`textContent`, а не `innerHTML` — защита от внедрения HTML через название. Сообщения об ошибках — в элементах рядом с полями, связанных через `aria-describedby`, с `aria-invalid` на поле. Значения полей формы при ошибке не трогаются; очищаются только после успешного добавления.

6. **id.** Монотонный счётчик, стартующий выше максимального существующего id (устойчиво после удаления и восстановления из хранилища).

7. **Вёрстка.** Одна колонка, `box-sizing: border-box`, `max-width: 100%`, `flex-wrap`, перенос длинных названий (`overflow-wrap: anywhere`), meta viewport. Фильтр — группа кнопок с подписью и `aria-pressed`.

8. **Необязательное хранение.** Обёртки `loadTasks/saveTasks` в `app.mjs` с `try/catch` вокруг каждого обращения к `localStorage` (включая сам доступ к свойству). Ошибка → видимая строка статуса «Данные не сохраняются между запусками», работа в памяти. Повреждённый JSON → стартовый набор. Реализуется последней группой задач и не блокирует остальные.

9. **Тесты.** `tests/acceptance.test.mjs` импортирует только `domain.mjs`: 25%/75%, независимость метрик от фильтра, валидация (пусто, пробелы, пустые/отрицательные часы, границы 0,5 и 24, шаг), пустое состояние, округление 33%. Результаты ручной проверки интерфейса фиксируются отдельно от автотестов.

## Risks / Trade-offs

- [Зелёные тесты не гарантируют корректный UI] → ручной прогон T1–T5 в браузере; результаты фиксируются честно, а если браузер не запускался — это прямо указывается.
- [localStorage при `file://` ведёт себя по-разному] → все обращения в try/catch, ограничение описывается в README, функция остаётся необязательной.
- [ES-модули из `file://` блокируются в части браузеров (CORS)] → в README указан запуск через `npx http-server`; в `index.html` — `<script type="module">`. Ограничение принимается.
- [Текстовое поле часов теряет числовую клавиатуру по умолчанию] → `inputmode="decimal"`.
