# Мини-трекер учебных задач — постановка (ДЗ1, вариант B)

Источник: «ДЗ 01 — Полная спецификация и инструкция», страницы 3–4. Текст перенесён без изменений.
Этот файл одинаковый в `direct/` и `with-spec/`. Не редактируйте его после начала попыток.

## Общая постановка мини-трекера

Результат: автономный мини-трекер без CDN, внешних библиотек и API-ключей. Для B - index.html, styles.css, app.mjs, domain.mjs и tests/acceptance.test.mjs.

Цель: мини-трекер учебных задач на неделю.

Данные задачи: id, title, hours, done. Стартовый пример: «Чтение» — 2 ч, done=true; «Практика» — 4 ч, done=false; «Повторение» — 2 ч, done=false.

Требования:

1. Добавление, удаление и переключение done реально меняют данные.
2. Название после trim непустое. Часы — число 0,5–24 с шагом 0,5. Пустое значение не равно нулю. Ошибка видна рядом с полем, данные формы сохраняются.
3. Прогресс = округление(100 × сумма часов done / сумма часов всех задач). Если задач нет — 0%, без NaN/Infinity.
4. Фильтр влияет только на видимый список. Итоговые часы и прогресс считаются по всем задачам.
5. При старте примера всего 8 ч, выполнено 2 ч, прогресс 25%. Если отметить «Практику» готовой — 6/8 и 75%.
6. Интерфейс читаем на ширине 390 px, без горизонтального скролла. Поля и кнопки подписаны.

Приёмка WHEN/THEN:

- WHEN включён фильтр «активные», THEN список меняется, прогресс остаётся 25%.
- WHEN введено пустое название или пустые/отрицательные часы, THEN задача не добавляется и видна ошибка.
- WHEN все задачи удалены, THEN итог 0 ч и прогресс 0%.
- WHEN «Практика» отмечена готовой, THEN прогресс 75%.

Необязательное улучшение: сохранять задачи в localStorage, а при недоступном хранилище показывать понятное сообщение и продолжать работу в памяти.

Документы и реализация выполняются разными запросами. При подготовке спецификации код не писать. Фактически проведённые проверки перечислять отдельно от предложенных; запуск браузера не заявлять, если его не было.

Хранилище между перезапусками - дополнительное улучшение. При открытии через file:// поведение localStorage зависит от браузера; ограничение нужно описать. Проверка узкого экрана полезна дополнительно.

## Пять общих проверок T1–T5

Выполните каждую проверку для обеих версий. Перед независимым сценарием восстановите исходные данные вручную или штатным сбросом, если он есть. Отдельная кнопка сброса не обязательна.

| Исходная задача | Часы | Статус  |
|-----------------|------|---------|
| Чтение          | 2    | Готово  |
| Практика        | 4    | Активно |
| Повторение      | 2    | Активно |

**T1 · Исходный пример**
Действие: Откройте три исходные задачи.
Ожидание: 3 задачи; всего 8 часов; выполнено 2 часа; прогресс 25% по часам, а не 1/3 по числу задач.

**T2 · Статус**
Действие: Отметьте «Практику» выполненной.
Ожидание: Выполнено 6 из 8 часов; прогресс 75%. И данные, и интерфейс изменились.

**T3 · Фильтр**
Действие: Верните исходные задачи; выберите «активные».
Ожидание: В списке только «Практика» и «Повторение»; общий прогресс остаётся 25%. Фильтр не меняет базу расчёта.

**T4 · Ошибки ввода**
Действие: По отдельности отправьте пустое название, пробелы, пустые и отрицательные часы. Дополнительно проверьте границы 0,5-24 и шаг 0,5.
Ожидание: Некорректная задача не добавляется, видна ошибка, введённые значения сохраняются для исправления.

**T5 · Пустое состояние**
Действие: Удалите все задачи.
Ожидание: 0 часов и 0%; нет NaN или Infinity; интерфейс продолжает работать.

Для B автоматизируйте расчёт 25%/75%, независимость метрик от фильтра, валидацию и пустое состояние. Форму, кнопки, текст ошибок и узкий экран проверьте вручную. Зелёные тесты функций не заменяют проверку интерфейса.
